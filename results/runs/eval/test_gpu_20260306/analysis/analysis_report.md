## 4. 问题定位（为什么指标差）

### A. 深度范围压缩严重（远处被系统性低估）
- 全帧 `pred/target` 中位比均值仅 `0.362`。
- 深度 `500-1000` 区间（像素占比 `21.3%`）: `pred/target≈0.025`，`delta1=0.0000`。
- 深度 `80-250` 区间（像素占比 `10.4%`）: `pred/target≈0.101`，`delta1=0.0016`。
- 含义: 模型对中远距离基本“压扁”到近距离，直接拉低 delta 系列指标。

### B. 近距离又过估，导致 AbsRel 进一步恶化
- 深度 `0-10` 区间（像素占比 `35.5%`）: `pred/target≈3.132`，`abs_rel=2.161`。
- 该区间平均正偏差 `+11.06` 深度单位。
- 含义: 近处过估 + 远处低估同时存在，不是“一个全局缩放因子”能修复的问题。

### C. 大量像素误差倍数过大，delta 指标自然很低
- 平均每帧 `ratio>2x` 像素占比 `77.3%`。
- 平均每帧 `ratio>4x` 像素占比 `54.0%`。
- 平均每帧预测命中最小裁剪值（`3.346`）比例 `13.9%`，说明输出下限饱和较明显。

### D. 训练检查点本身处于“验证/早期”状态
- 当前评估模型: `s2d_checkpoints/train_verify_20260306/model_best.pth.tar`。
- 对应配置 `s2d_checkpoints/train_verify_20260306/config.json` 中 `trainer.epochs = 1`，训练轮次极少，欠拟合风险高。
- 这与当前“深度分布被压缩”的现象一致。

## 6. 建议的修复优先级
1. 优先替换为充分训练的 checkpoint（先排除“训练不足”变量）。
2. 针对深度分布压缩做校准: 检查训练/测试 `reg_factor`、目标归一化范围、输出激活与反变换链路是否一致。
3. 重新评估损失权重（SI/梯度损失）对中远距监督不足的问题，可增加绝对尺度约束或分段加权。
4. 对 `target==1`（反变换后 1000）区域确认语义（真实远距 vs 无效值），必要时增加有效掩码评估。
